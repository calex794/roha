## Новые подтверждённые направления

1. **Защита от зависания при закрытии пользовательского маршрута** — [KingYoSun eef6af6](https://github.com/KingYoSun/iroh/commit/eef6af69364b5df1aa33c30e4c5731aad9d32046). В сообщении и патче объяснён пограничный случай: если отключить пользовательский маршрут после открытия relay, но до получения PATH_RESPONSE, управление PATH_ABANDON может уйти в уже выброшенный путь. Тогда передача данных и обновлений управления потоком может зависнуть. Предлагается дождаться установленного другого маршрута перед закрытием старого; иначе ограниченный срок ожидания. **Требуется воспроизводимый опыт Roha/noq:** соединение A через custom, открыть relay B, удалить A до подтверждения B, проверить непрерывность потоков и повторную передачу. Не реализовано.

2. **Добавление пользовательского пути в живую сессию** — [KingYoSun c47e860](https://github.com/KingYoSun/iroh/commit/c47e860f7573841ff86b51bfa1984777bffca274). Сообщение коммита прямо указывает, что это перенос [n0-computer/iroh PR #4565](https://github.com/n0-computer/iroh/pull/4565), commit 6099b7168e: **не выдавать за самостоятельное изобретение форка**. API `Endpoint::add_remote_addrs` передаёт новые пользовательские адреса работающим remote actors, которые открывают путь через `open_path_on_all_conns`. Применимо к WebRTC-пути, появившемуся после старта QUIC. Проверить, не присутствует ли уже в нашей Roha; затем тест на отсутствие повторного соединения и ограничение очереди адресов.

3. **Перевыбор пути при смене пользовательской политики** — [bluestarburst 2bf4c5a](https://github.com/bluestarburst/iroh/commit/2bf4c5ae8ab068e3d680d12f041e56a8e41c3042). API `request_path_reselection(endpoint_id)` через ограниченную очередь сообщений передаёт `ReselectPath` работающему актору, вызывающему существующий `select_path()`. Не создаёт новый QUIC-сеанс, не начинает поиск адресов. Для Акулы: правила предпочтения LAN/relay/custom, переключение тарифа/стоимости, пользовательский приоритет маршрута. Проверить существующие API управления предпочтениями и тесты на неизменность соединения.

4. **Последний отозванный путь и зависшее соединение** — [KingYoSun 2acfa7e](https://github.com/KingYoSun/iroh/commit/2acfa7e1132dc2d018bd4d80abd6ab5d442a7d18). При потере единственного пользовательского пути до поступления remote connection IDs закрытие невозможно, а следующий сеанс может выбирать уже мёртвый путь. Предлагается исключение из выбора и ограничение времени ожидания до 3 секунд. Проверять в совокупности с первым случаем, так как раннее закрытие пути может приводить к другой потере данных.

## Очерёдность приёмки
- **P0:** воспроизвести потерю DATA и управляющих обновлений при удалении пути, затем испытать переключение до закрытия, и переполнение очередей Roha/noq.
- **P0:** безопасность привязки подписи relay к имени посредника (см. CROSS-FORK-GAPS.md).
- **P1:** добавить новые пользовательские адреса без переподключения и смену политики выбора пути.
- **P1:** распределённая идентичность нескольких устройств и отзыв доступа; пока только теория.
- Все изменения разрабатываются на наших форках Roha + noq с их взаимными зависимостями. Не переносить чужие абсолютные пути. Тесты сначала; слияния в main до приёмки нет.
